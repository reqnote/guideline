コーディング規約

保守性・可読性・一貫性を保つための開発ルールです。

全般

  • インデントはスペース 2文字（タブ禁止）
  • 文字コードは UTF-8（BOMなし）
  • 改行コードは LF（CRLF禁止）
  • 1行の最大文字数は 120文字 を目安とする
  • ファイル末尾に空行を1行入れる
  • コミットメッセージは 日本語 で体言止め（例：「ユーザー一覧APIを追加」）

HTML

  • セマンティックタグを優先（section, article, nav, main など）
  • すべての画像に alt 属性を設定する
  • フォームの input には必ず label を紐付ける（for 属性または aria-label）
  • 属性値はダブルクォートで囲む
<!-- Good -->
<section class="user-list">
  <h2>ユーザー一覧</h2>
  <ul>
    <li><a href="/users/1">山田 太郎</a></li>
  </ul>
</section>

<!-- Bad -->
<div class='user-list'>
  <div>ユーザー一覧</div>
</div>

CSS / スタイル

  • 色・サイズはすべて CSS カスタムプロパティ（variables.css）で管理する
  • Bootstrap のユーティリティクラス（d-flex, gap-2, text-muted 等）を積極活用する
  • クラス名は ケバブケース（例：card-title, form-group）
  • !important は原則禁止。Bootstrap の上書きのみ例外として許可
  • メディアクエリは モバイルファースト（min-width で記述）
/* Good — CSS変数使用 */
.my-btn {
  background: var(--g-primary);
  border-radius: var(--g-radius);
}

/* Bad — ハードコード */
.my-btn {
  background: #1A3F7A !important;
  border-radius: 8px;
}

JavaScript / TypeScript

  • 変数・関数名は キャメルケース（例：getUserList）
  • 定数は アッパースネークケース（例：MAX_PAGE_SIZE）
  • クラス名は パスカルケース（例：UserService）
  • var は禁止。const を優先、再代入が必要な場合のみ let を使う
  • 非同期処理は async/await を使用
  • TypeScript の型は明示的に定義する（any 禁止）
// Good
const MAX_RETRY = 3;

async function fetchUserById(userId: string): Promise<User> {
  const response = await api.get(`/users/${userId}`);
  return response.data;
}

// Bad
var x = 3;
function f(id: any) { ... }

API 設計

  • REST API のパスは ケバブケース（例：/api/user-profiles）
  • リソース名は 複数形（例：/users、/orders）
  • レスポンスは常に { data, error, meta } の統一形式で返す
  • HTTPステータスコードを正しく使用する（200, 201, 400, 401, 404, 500）
  • バージョン管理は URL パスに含める（例：/api/v1/users）

ドキュメント規約

仕様書・設計書・議事録などの作成・管理ルールです。

共通ルール

  • 全ドキュメントはバージョン管理（Git）で管理する
  • ファイル形式は Markdown (.md) を基本とする
  • ドキュメント冒頭にヘッダー（タイトル / 作成者 / 日付 / バージョン）を記載する
  • 更新履歴を末尾に残す

ユーザーストーリー記法

形式：As a [ロール], I want [機能], so that [目的/価値]

例：
「管理者として、ユーザー一覧をCSVでエクスポートしたい。
なぜなら、月次レポートの作成に活用できるから。」

受入条件（Acceptance Criteria）：

  • 一覧画面に「CSVエクスポート」ボタンが表示される
  • ボタンクリックで UTF-8 BOM 付きCSVファイルがダウンロードされる
  • エクスポートされるカラムは：ID / 氏名 / メール / ロール / 登録日
  • フィルタ適用中はフィルタ後のデータのみエクスポートされる

API仕様書テンプレート

## GET /api/v1/users

ユーザー一覧を取得する。

### リクエスト

| パラメータ | 型     | 必須 | 説明                      |
|------------|--------|------|---------------------------|
| page       | number | 任意 | ページ番号（デフォルト:1）|
| limit      | number | 任意 | 取得件数（最大:100）      |
| search     | string | 任意 | 氏名・メールで絞り込み    |

### レスポンス (200 OK)

```json
{
  "data": [
    { "id": "u_001", "name": "山田 太郎", "email": "yamada@example.com" }
  ],
  "meta": { "total": 120, "page": 1, "limit": 20 },
  "error": null
}
```

### エラーレスポンス

| コード | 説明                  |
|--------|-----------------------|
| 400    | リクエストパラメータ不正 |
| 401    | 未認証                |
| 403    | 権限不足              |
